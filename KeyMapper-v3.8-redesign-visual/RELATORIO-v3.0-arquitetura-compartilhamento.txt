KEYMAPPER v3.0 — RELATÓRIO DE ALTERAÇÕES

BASE
- Base usada: projeto-fonte KeyMapper-v2.6-ajustes-aim.zip, fornecido na conversa.
- Nenhuma URL de repositório GitHub foi informada; esta entrega é uma alteração da cópia local do projeto, não um commit remoto.

IMPLEMENTADO
1. Compartilhamento nativo Android:
   - Compartilhar Configurações exporta AppSettings.toJson() via Intent.ACTION_SEND e chooser nativo.
   - Compartilhar Log de Erro exporta modelo/fabricante, versão Android/API, resolução/densidade/taxa de atualização, RAM, DeX, estado de Shizuku, permissão de overlay, estado do serviço e último crash registrado.
2. CrashReporter:
   - Registra o último crash não tratado em SharedPreferences, com tamanho limitado, e delega ao handler anterior.
   - O relatório só é compartilhado quando o usuário aciona explicitamente a função.
3. Apresentação / MVVM:
   - Adicionado SettingsViewModel com StateFlow, atualização e gravação assíncrona em Dispatchers.IO.
   - HomeScreen e SettingsScreen consomem o estado do ViewModel.
4. Dados / composição:
   - SettingsRepository permanece baseado em Preferences DataStore.
   - KeyMapperApp mantém uma instância compartilhada do repositório para Activity e Service (injeção manual).
5. Domínio:
   - SensitivityEngine foi movido para o pacote domain e deixou de depender diretamente de AppSettings; a matemática permanece Kotlin puro.
6. Ciclo de vida:
   - MappingService limpa callbacks, referências de overlay, watcher, motor e injetor no encerramento; listeners de DisplayManager/InputManager já eram removidos e permanecem assim.

LIMITAÇÕES / NÃO DECLARAR COMO CONCLUÍDO
- Hilt não foi adicionado: a regra de preservar os arquivos Gradle impede adicionar plugin/dependências necessários. Foi usada composição manual.
- MappingEngine continua sendo um adaptador/orquestrador dependente de Android (RectF, KeyEvent, MotionEvent e TouchInjector); não foi reescrito integralmente como domínio puro porque isso exigiria redesenhar o pipeline de entrada.
- CaptureView de 1x1 continua focável quando precisa capturar teclado/mouse. Em Android, uma janela overlay focável pode tomar o foco do jogo; torná-la não focável pode impedir a captura de teclado. Não é possível prometer simultaneamente foco do jogo e captura global de teclas com essa janela sem outro mecanismo suportado pelo sistema.
- QUERY_ALL_PACKAGES já existia no Manifest; não foi alterado.
- Os recursos de injeção/Shizuku e o comportamento de mouse infinito não foram validados em dispositivo físico nesta entrega.
- Compilação Android não foi executada porque este ambiente não possui Gradle/Android SDK configurados. O ZIP passou pela verificação estrutural, não por build.
